# v0.19.3 mitigations + sandbox config audit — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose agentsh v0.19.3's new seccomp surface (`socket_rules`, `mitigation_sets`, `mitigation_dirs`), fill pre-existing gaps in `seccompDetails` / `sandboxLimits` / `fuse` / `networkIntercept` / `cgroups` / `unixSockets`, and enable `dirtyfrag-conservative` by default in adapters that already ship seccomp defaults (sprites, freestyle, runloop, exe).

**Architecture:** All work is in TypeScript types + the existing `generateServerConfig` serializer in `src/core/config.ts`. New fields follow the established `if (X !== undefined) sec.snake_case = ...` pattern. One new file `src/core/mitigations.ts` exports a `KNOWN_MITIGATIONS` constant. Hand-rolled validation, no Zod (matches existing style in this file). All additions optional and back-compat — `execve: boolean` keeps working alongside the new `execveDetails` sub-object.

**Tech Stack:** TypeScript 5.7, vitest 3, js-yaml 4 (already in deps).

**Spec:** `docs/superpowers/specs/2026-05-08-v0.19.3-mitigations-and-config-audit-design.md`

**Branch:** Run all work on a feature branch off `main` (current branch `config-audit-spec` may be reused or replaced — confirm with the user before starting).

/**
 * Built-in agentsh mitigation set IDs that secure-sandbox knows about.
 *
 * Pass these to `seccompDetails.mitigationSets` instead of raw strings to
 * get autocomplete and a single update point when agentsh ships new
 * built-in mitigations.
 *
 * Reference: `internal/config/mitigations/` in canyonroad/agentsh.
 */
export const KNOWN_MITIGATIONS = {
  /**
   * Conservative mitigation for the Openwall Dirty Frag advisory dated
   * May 7 2026. Expands to two socket_rules: AF_RXRPC and
   * AF_NETLINK+NETLINK_XFRM, both with action `log_and_kill`.
   * Does NOT block all AF_NETLINK.
   */
  dirtyfragConservative: 'dirtyfrag-conservative',
} as const;

export type KnownMitigation =
  typeof KNOWN_MITIGATIONS[keyof typeof KNOWN_MITIGATIONS];

- [ ] **Step 3: Add the validator**

In `src/core/config.ts`, above `generateServerConfig` (or near the top of the file with other helpers), add:

```ts
function validateSeccompDetails(seccomp: NonNullable<ServerConfigOpts['seccompDetails']>): void {
  if (seccomp.mitigationDirs) {
    seccomp.mitigationDirs.forEach((path, i) => {
      if (!path.startsWith('/')) {
        throw new Error(`seccompDetails.mitigationDirs[${i}]: must be an absolute path, got "${path}"`);
      }
    });
  }
  if (seccomp.socketRules) {
    const names = new Set<string>();
    seccomp.socketRules.forEach((r, i) => {
      if (names.has(r.name)) {
        throw new Error(`seccompDetails.socketRules[${i}].name: duplicate name "${r.name}"`);
      }
      names.add(r.name);
      if (r.protocol?.startsWith('NETLINK_') && r.family !== 'AF_NETLINK') {
        throw new Error(`seccompDetails.socketRules[${i}].protocol: NETLINK_* is only valid with family AF_NETLINK`);
      }
    });
  }
  if (seccomp.syscalls) {
    if (seccomp.syscalls.defaultAction === 'allow' && (!seccomp.syscalls.block || seccomp.syscalls.block.length === 0)) {
      throw new Error('seccompDetails.syscalls: defaultAction "allow" requires non-empty block list');
    }
  }
}
```
